Estudo de caso · E-commerce

Lara Store

Loja de moda feminina em Irecê-BA, migrada de um protótipo estático em HTML para um app React completo, com painel administrativo próprio para a lojista rodar o negócio sem depender de mim no dia a dia.

React 19 TypeScript estrito Vite 8 Firebase (Firestore + Auth) React Router Vitest + Testing Library Playwright (visual)
Visão geral

Do WhatsApp para uma loja de verdade

A Lara Store vendia pelo Instagram e WhatsApp. O projeto começou como um protótipo estático (HTML/CSS/JS) pra validar a experiência visual e comportamental, e migrou pra um app React + TypeScript com Firebase, mantendo o fechamento do pedido pelo WhatsApp (o canal que a cliente já confia), mas com catálogo, estoque, cupom, frete e financeiro gerenciados num painel próprio.

estoque reservado por peça e tamanho, sem overbooking cupom por percentual ou valor fixo frete calculado por faixa de CEP regras do Firestore testadas com emulator 35+ cenários de teste automatizado

Feature em destaque

Estoque que reserva na hora, sem vender o que não existe

Cada peça tem estoque por tamanho. Ao entrar na sacola, o estoque é decrementado como reserva — se o tamanho zera, ele some das opções na hora, pra ninguém comprar o que não tem mais. Essa transação é o que o projeto trata como não-negociável: não é lazy nisso.

Feature em destaque

Frete por faixa de CEP, calculado na ficha da peça

A lojista cadastra faixas de CEP com prazo e valor de referência (Irecê grátis no mesmo dia, Bahia e resto do Brasil com preço à parte). A cliente digita o CEP na ficha da peça e vê o prazo e o valor na hora, sem sair da página.

Sob o capô

Como foi construído

React 19 + TypeScript estrito + Vite 8, com React Router pra URL por página. Firebase (Firestore + Auth) como backend, sem servidor próprio. Vitest e Testing Library cobrem a interface, com regra fixa de esperar navegação assíncrona (findBy, nunca getBy) pra não gerar falso negativo. Playwright cobre regressão visual. As regras do Firestore rodam contra o emulator, isoladas dos testes de UI — regra sem teste não publica. Hooks de git versionados (pre-commit com gitleaks, pre-push com lint e teste) porque o repositório é privado no plano Free do GitHub, sem CI verde obrigatório antes do merge.
